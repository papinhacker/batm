# auto-testing (BATM)
Фреймворк автотестов для сервисов BATM. API тестируемых систем — Kafka, S3,
PostgreSQL, немного REST. UI нет.
## Стек
- Java 17, Maven, TestNG, Allure, Jackson, Lombok, kafka-clients, AWS SDK v2
  (S3), Awaitility.
- Ядро: src/main/java/ru/vtb/core (клиенты, модели Kafka, утилиты).
- Тесты: src/test/java/ru/vtb/api/tests, сьюты TestXML/.
- Запуск в CI: fat-jar (maven-assembly,
  ru.vtb.core.common.test_runners.TestsRunner) с аргументом-сьютом;
  исходники и src/*/resources лежат рядом с jar (user.dir = корень проекта).
- Окружения: ift, preprod (физически разные контуры). dev больше не
  поддерживается.
## Команды
- Сборка: mvn -q test-compile
- Офлайн-тесты фреймворка (без стенда): mvn -q test -Pselftest
- Fat-jar: mvn -q package -DskipTests
## Правила работы
- Меняй только то, что сказано в задаче. Не переформатируй и не
  переименовывай попутно.
- Исправляй сам код. Никаких обходных решений: скриптов рядом, обёрток поверх
  сломанного метода, отключения проверок.
  Итерационный план исправления auto-testing через Claude Code
  Page 3 of 25
- Не додумывай. Если не хватает данных (ожидаемые значения, форматы
  сообщений, поведение сервиса) —
  остановись и спроси. Не подгоняй ожидаемые значения под фактические.
- Не ослабляй проверки, чтобы тест прошёл. Упавший тест после исправления
  фреймворка — возможный баг системы; сообщи о нём.
- Исключения не глотать. Ошибка инфраструктуры (Kafka/S3/БД) должна ронять
  тест с понятным сообщением.
- Никаких System.exit вне TestsRunner. Никаких Thread.sleep в тестах — только
  Awaitility.
- Не коммить расшифрованные пароли, ключи и данные со стендов.
- После изменений запускай сборку и офлайн-тесты. В конце перечисли
  изменённые файлы и то, что нужно проверить на стенде.
## Конвенции
- Новый тест: @Test(groups = {"<имя-сервиса>"}) + @TmsLink("BATM-xxx");
  однопоточные — доп. группа "serial".
- Поиск сообщений Kafka — только по уникальному id теста, не по подстроке с
  суммой/датой.
