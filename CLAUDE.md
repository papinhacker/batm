# auto-testing (BATM)

Фреймворк автотестов для сервисов BATM. API тестируемых систем — Kafka, S3, PostgreSQL, немного REST. UI нет.

## Стек и запуск
- Java 17, Maven, TestNG 7.4.0 (не обновлять без промпта 7.1 — ломается вложение лога в Allure),
  Allure, Jackson, Lombok, kafka-clients, AWS SDK v2 (S3), Awaitility.
- Ядро: src/main/java/ru/vtb/core. Тесты: src/test/java/ru/vtb/api/tests. Архив: ru.vtb.api.tests.archive (не запускается).
- CI: fat-jar (ru.vtb.core.common.test_runners.TestsRunner) на TeamCity, Jenkins и собственной CI. Исходники
  и src/*/resources лежат рядом с jar. Ничего специфичного для одной CI: только -D-свойства, файлы и код возврата.
- Окружения (-Dcenv): test = ИФТ (ift, стандартный тестовый контур) и preprod — разные контуры.
  Файл свойств preprod живёт только на своём контуре. dev мёртв.
- Kafka-кластеры: BATM, UASP, ODS (ru.vtb.core.data.static_data.KafkaCluster).

## Команды
- Сборка: mvn -q test-compile
- Офлайн-тесты фреймворка: mvn -q test -Pselftest
- Fat-jar: mvn -q package -DskipTests

## Ограничения среды
- Сетевого доступа к стендам (ift/preprod) нет. Не пытайся запускать тесты на стенде и не подбирай
  данные стенда (имена топиков, колонки, форматы) — спрашивай.
- Данных со стенда (DDL, выгрузки, логи) не будет — только код репозитория и ответы пользователя.
- Пароли лежат в properties в зашифрованном виде; ключ тебе не дают — не проси его.

## Правила работы
- Меняй только то, что сказано в задаче. Не переформатируй и не переименовывай попутно.
- Исправляй сам код. Никаких обходных решений: скриптов рядом, обёрток поверх сломанного метода, отключения проверок.
- Не додумывай. Не хватает данных (ожидаемые значения, типы колонок, форматы сообщений, поведение
  сервиса) — остановись и спроси. Не подгоняй ожидаемые значения под фактические.
- Не ослабляй проверки, чтобы тест прошёл. Упавший тест после исправления фреймворка — возможный баг системы.
- Исключения не глотать: ошибка Kafka/S3/БД роняет тест с понятным сообщением.
- Никаких System.exit вне TestsRunner. Никаких Thread.sleep в тестах — только Awaitility.
- Архивные тесты не чинить и не мигрировать; если они не компилируются после изменений — скажи, не удаляй.
- В конце перечисли изменённые файлы и что нужно проверить на ift (какие сьюты).

## Конвенции
- Новый тест: @Test(groups = {"<имя-сервиса>"}) + @TmsLink("BATM-xxx"); однопоточные — доп. группа "serial".
- Поиск сообщений Kafka — по уникальному id (rrn, instructionId, messageId), не по имени файла и не по сумме.
- Проверки БД для таблиц, у которых есть entity, — только через репозитории (ru.vtb.core.db), а не через Map
  и строковые имена колонок. Нет entity — пока DBHelper.
- Entity БД генерирует пользователь (JPA Buddy) в ru.vtb.core.db.entity.<бд>. Не создавай и не меняй
  entity без прямой просьбы; не хватает таблицы или поля — скажи, что догенерировать.
- Hibernate никогда не меняет схему (hbm2ddl = none; проверка маппинга на стенде — -Ddb.validate=true).
